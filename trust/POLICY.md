# 信任政策（TRUST POLICY）

> 一句话：**信什么、为什么信、哪块没覆盖**。
> 这份文件不是许愿池，是可被反驳的陈述——每条都指向一个能跑的命令或一个可读的文件。

本项目的最终目标写在 [VISION.md](../VISION.md)：产物要么**可审**，要么**可判合格**。
政策只回答一件事：**谁来承担「这段代码做的是它说的事」这个判断。**

---

## 1. 判定规则（唯一一条）

```
开源可查  +  规模在可读范围内  +  来源可核（版本串 + 哈希）
        ⇒  可信任

不满足任一条  ⇒  不主张可审，只记录哈希（"我用的就是这个字节"）
```

“规模可读”是**人的判断**，不是自动判据。这里按人能真正读完的尺度划（≈ 数千行量级）；
超出的部分不假装读过，改走“可判合格”（见 §4）。

## 3. 出处核验（C 层，新增）

`trust/manifest.json` 只锁**“我上次记的哈希”**（防本地漂移），
但它**证明不了“与上游一致”**——那只证明“自我记录以来没变”。
所以另立 `trust/thirdparty.json`：记录 `upstream` 仓 + `declared_version` + 哈希。

```
python3 trust/manifest.py --verify-thirdparty
```

判据：文件里自己声明的版本串（如 `stb_image - v2.28`）必须与 `declared_version` 一致，
哈希必须与记录一致。离线可跑，不依赖网络。

当前：**4 项，版本串与哈希均对**（stb_image v2.28 / resize v0.90 / write v1.16 / truetype v1.26）。

**去重事实**：`cpp/annot/stb_*.h` 是**转发头**（`#include "../thirdparty/stb/..."`），
不是第二份副本。所以 vendored 面只有一处，升级只需改一处。
（这条以前是隐性的，现在写下来——否则“我们到底有几份 stb”会变成传闻。）

## 4. 后端为什么“不可审但可接受”

Chez + gcc 合计几十万行，读不完，就是**不审**。接受它的理由不是“它可信”，是三条工程约定：

1. **它的输入被约束得很窄**：Chez 只吃我们自己生成的 Scheme IR，不吃任意用户输入。
   所以需要关心的不是 35 万行，而是**被 IR 触发到的那一小片路径**。
2. **它可替换**：A 层 1,653 行信任根的存在，意味着后端是**耗材**而非信任根。
   换后端时，判据不是“新的后端可信吗”，而是“**换掉它，谁会报警**”。
3. **报警是自动的**：~~E3+E5 负责这件事~~ —— **实测证明这句是错的**，见 §4.1。
   真正报警的是 E4/E7（对外部 oracle 的行为差分），不是 E3/E5。

**「可替换」必须被演练过，否则只是话。** 已于 2026-11-20 演练，结果如下。

### 4.1 后端替换演练（实测，2026-11-20）

**下毒方式**：`CHEZ_SCHEME` 指向一个 wrapper，它在真 Chez 编译前篡改 IR 里两个字面量
（`"True"→"TruE"`、`"None"→"NonE"`）。产物**照常构建、照常运行**，只是行为错了：

```
$ ./dist/drill_poison        # 基线应为 True/None/3
TruE
NonE
3
```

**十个判据谁响了**：

| 判据 | 结果 | 说明 |
|---|---|---|
| **E5 固定点** | **全绿，哈希与基线一字不差**（g1 `6d768543…` / g2 `bcb85087…` / g3 `bcb85087…`） | **完全无感**。固定点只问“编译器能否稳定复制自己”；均匀下毒自然稳定复制自己——`fixpoint.sh` 头注释里那句“自洽的后门同样能通过固定点”这次有了实证 |
| **E3 IR 差分** | **红，但是「漏进来」的，不是设计使然** | E3 比的是两份 **Python** 翻译器的 IR（`grep -c "scheme\|chez" = 0`），本来与后端无关。红是因为自举翻译器**运行时**要一份 boot 产物：缓存里已有干净 boot 时 → **绿**（实测 `CHEZ_SCHEME` 单独下毒，`ok(规范化) fail=0`）；缓存为空、让下毒后端去建 boot 时 → **红**。即：**能不能看见，取决于缓存里有没有旧 boot**，不是因为它检查了后端 |
| **E4 语义差分** | **红（唯一硬报警）** | CPython 打 `True`，ELF 打 `TruE`。因为 oracle 是 **CPython 本体**，不受后端影响 |

**结论（三句话）**：

1. **E3 不碰后端**：`grep -c "scheme\|chez" staticpy/check_translate.sh` = **0**，它比的是两份
   Python 翻译器的 IR。红绿取决于缓存里有没有旧 boot（§4.1 表），是**漏入**而非判据；
   一个只污染产物代码路径、不碰翻译器运行时的后端，E3 全程看不见。
2. **E5 结构上看不见均匀下毒**：它是自洽性检验，而“稳定的错”正是自洽的。
3. **唯一可靠的后端报警来自对外部 oracle 的行为差分（E4/E7）**——判据里必须有一个
   **不经过后端**的参照物（CPython / Pillow / zlib）。这是可替换性的真实边界。

**代价**：一次演练 = wrapper 十行 + 六条命令，全程 < 5 秒（构建 0.34 s，fixpoint 1.6 s）。
比读 Chez 便宜三个数量级，而结论更硬——**它把一句主张变成了可复现的失败**。

## 5. 构建记账（让上面的主张可复现）

每次构建产出 `<产品>.build-info.json`：

```json
{
  "product": "app",
  "built_at": "2026-11-20T23:50:58+08:00",
  "chez_version": "10.5.0-pre-release.1",
  "chez_dir": "/opt/ChezScheme/ta6le",
  "chez_boot_md5": "…",          // petite.boot+scheme.boot 指纹 = Chez 的真实身份
  "gcc_version": "13.3.0",
  "build_inputs_md5": "…"
}
```

**这不是 gate，只是账本**——不阻断任何构建。它的用途只有一个：
让“换掉后端看差分会不会红”这类验证将来**别人也能重跑**。没有它，版本就是传闻。

## 7. 与 VISION 的对应

- 「**可审的信任根**」→ A 层 1,653 行。
- 「**再生成要么确定，要么可判合格**」→ §4：后端不审，但要求**换它时差分变红**。
- 「**没有可检查的固定表示，就没有信任**」→ §5 的 `build-info.json` 与
  `manifest.json` 的 soname→sha256 就是这个“固定表示”。

> 立场：**开源 + 规模可控 = 可信任**；但“可信”是**来源判断**，
> 而“这台机器上跑的是哪一份”要靠**固定表示**。两件事都要，缺一条就只剩传闻。
